# Backend contract and dependency inventory

Inspected `backend/routes/api.php`, the API controllers, role middleware, models, seed definitions, configuration, and feature tests. All paths below are relative to `/api`. Backend source and migrations are unchanged.

## Existing APIs

| Endpoint | Access | Request | Confirmed response / mobile use |
| --- | --- | --- | --- |
| POST `/auth/login` | Public | email, password | token and user; unsupported roles rejected and issued token revocation attempted |
| POST `/auth/register` | Public | name ≤255, unique email ≤255, password ≥8, password_confirmation | 201 token/user; backend assigns `residents` |
| GET `/auth/me` | Sanctum Bearer | None | `{user}`; restore/verify session; only 401 invalidates token |
| PATCH `/auth/profile` | Sanctum Bearer | name/email required; contact_number ≤32; office/jurisdiction ≤255 optional | `{message,user}`; role/password excluded; backend also supports optional JPEG/PNG avatar ≤2MB, not implemented here |
| POST `/auth/logout` | Sanctum Bearer | None | Revokes current token; local logout distinguishes failed server revocation |
| POST `/forgot-password` | Public | email | generic message, data.challenge_id (may be empty), expires_in, resend_available_in |
| POST `/forgot-password/verify-otp` | Public | challenge_id exactly 32 chars, otp exactly 6 digits | data.reset_token (48 chars), expires_in; backend enforces expiry and attempts |
| POST `/forgot-password/resend-otp` | Public | challenge_id exactly 32 chars | Generic message, data with timing; backend enforces cooldown/rate limits |
| POST `/forgot-password/reset` | Public | reset_token exactly 48 chars, password ≥8, password_confirmation | Resets password; revokes existing tokens; backend enforces single use/expiry |
| POST `/sos-requests` | Public | Nine fields detailed below | 201 `{data}` including generated id, status, received_at |
| GET `/sos-requests` | admin/campmanager | None | `{data:[]}` newest first; Camp Manager emergency reports use it |
| PATCH `/sos-requests/{id}` | admin/campmanager | status: Pending, Coming, Resolved | Existing endpoint; status management is left to existing admin UI in this scope |

SOS request: `name` ≤255, `contact` ≤32, `location` ≤255, latitude numeric −90…90, longitude numeric −180…180, `type` ≤255, category `Medical | Flood assistance | Evacuation`, priority `Critical | High | Medium`, description ≤2000. All nine fields are required. Although the current public controller accepts an optional status, the mobile whitelist **never submits it**. Backend IDs and receipts are not generated by mobile. Invalid coordinates cannot be replaced by made-up defaults.

User response: id, name, email, role, contact_number, office, jurisdiction, avatar_url. Only exact `residents` and `campmanager` role strings enter mobile protected tabs. Backend authorization remains authoritative for authenticated actions.

## Missing support; no fabricated data

| Requirement | Missing backend/data | Current mobile behavior |
| --- | --- | --- |
| Assigned evacuation center | manager assignment endpoint and authorization | Unavailable state |
| Center information | verified center catalog, geometry, conditions, status | Unavailable state |
| Occupancy / capacity changes | authorized transactional occupancy and capacity API | Disabled action, no numerical totals |
| Facility reporting | validation, persistence, center authorization | Disabled action |
| Evacuee registration / monitoring | records, search/filter/pagination, privacy policy, center permissions | Prepared search/filter/form; submission disabled |
| Official disaster alerts | trusted authority/source, timestamps, severity, expiry, delivery API | Unavailable state; caller SOS reports are separately labeled |
| Evacuation routing | verified safe centers/routes and current closures | Unavailable state; no route is suggested |
| Geographic hazard layers | georeferenced datasets/CRS/extent/currentness | Original images only, no geographic overlays |
| SOS exactly-once retry | backend idempotency keys and public receipt lookup | Uncertain submissions cannot retry automatically or through a resend button |
| Resident SOS tracking | owner/public scoped receipt lookup and authorization | Submission-time receipt only; no live dispatch claim |
| Push notification lifecycle | device token registration/removal, FCM credentials and authorized alert dispatch | Preparation only, inactive |
| Offline interactive map | licensed offline-enabled tile dataset/style/assets | Online basemap plus bundled image references; no guaranteed offline map |

## Backend considerations for future work

These are observations, not backend modifications: public SOS presently accepts caller status; the mobile app omits it but other clients could still submit it. SOS sequential ID allocation should be assessed for concurrent inserts before broader use. OTP mail delivery requires a functioning local mail configuration; a generic success message does not prove delivery. Center assignment, occupancy, and evacuee permissions need backend enforcement before enabling their controls.
