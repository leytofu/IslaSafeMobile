# IslaSafe mobile — local capstone development

React Native / Expo SDK **57.0.28**, TypeScript, Expo Router, MapLibre React Native **11.5.0**. All application changes are contained in `mobile/`. Backend source, migrations, and the admin frontend are not changed. This project does not configure EAS, Play Console, production signing, production hosting, or live push notifications. `ISLASAFE_BUILD=production` deliberately rejects configuration.

## Expo Go on a physical phone

Run `npm start -- --lan --clear`, scan the Expo Go QR code, and reload the project after pulling changes. Home and Hazard Map use bundled MapLibre GL JS 6.10.0 through Expo Go’s included WebView when native MapLibre is absent. No APK is needed for this path. See [phone map setup](docs/PHONE_MAP_SETUP.md). Existing custom IslaSafe development builds retain native MapLibre; use `npm run start:dev-client` for those builds.

## Local Android setup

Use Node 22.13+ (tested here with Node 24.15), Android Studio, its bundled JDK, Android SDK platform/build tools 36, and the existing `Pixel_6` AVD. The first local Gradle build downloads free dependencies and can take several minutes. The optional MapLibre React Native renderer needs a custom build. Expo Go uses the MapLibre GL JS fallback described above.

From PowerShell in `mobile/`:

```powershell
npm ci
Copy-Item .env.example .env
$env:JAVA_HOME = 'C:/Program Files/Android/Android Studio/jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA/Android/Sdk"
$env:PATH = "$env:JAVA_HOME/bin;$env:ANDROID_HOME/platform-tools;$env:PATH"
# Start Pixel_6 in Android Studio's Device Manager, then:
npx expo run:android --device Pixel_6
```

For later launches, use `npm start` and press `a`. Rebuild with `npx expo run:android --device Pixel_6` after native dependencies or app configuration change. SDK 57 prebuild recreates native folders by default; `npx expo prebuild --platform android --no-clean` applies configuration changes incrementally when appropriate. Native folders are generated by Expo; configure them through `app.config.ts`, not manual edits. The included short-path plugin places CMake staging files in ignored `mobile/.c/` to avoid Windows Ninja's 260-character path failure at this checkout location. Only a local debug development build is intended. Do not run cloud builds, releases, store submissions, or production deployments.

If the development client cannot reach the computer's LAN address, use the local adb tunnel:

```powershell
adb reverse tcp:8081 tcp:8081
adb shell am start -a android.intent.action.VIEW -d 'exp+islasafe-mobile://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8081' ph.islasafe.mobile
```

Development builds still need Metro for loading/reloading JavaScript. Offline behavior refers to the running app without access to its API/Internet; an offline cold start cannot be assumed if Metro is also unavailable. A local adb tunnel can keep Metro reachable while testing an unavailable API. This limitation is separate from the embedded map documents and encrypted records.

In another terminal, start the existing local API from `backend/`:

```powershell
php artisan serve --host=127.0.0.1 --port=8000
```

MySQL and the existing database must already be configured. This implementation does not migrate or reseed the database. Existing seed definitions describe `resident@islasafe.test` and `camp@islasafe.test` with password `password`; these work only if those accounts were previously seeded.

## API configuration

`EXPO_PUBLIC_API_BASE_URL` is required for your environment; its default development value is `http://10.0.2.2:8000/api` for the Android emulator. `localhost` on the emulator is the emulator itself. For physical Android devices, set the variable to your computer's actual LAN IPv4 address, start Laravel with `--host=0.0.0.0`, and ensure both devices share the local network and the firewall permits port 8000. Find your address with `ipconfig`; do not copy an invented example address. Restart Metro after changing variables.

For browser preview only:

```powershell
$env:EXPO_PUBLIC_API_BASE_URL = 'http://127.0.0.1:8000/api'
npx expo start --web --port 8082
```

Browser preview intentionally stores credentials and SOS records **only in memory**. A browser reload discards them. Native map, Android permissions, encryption, and persistent sessions must be tested on Android. Run separate Metro processes with the appropriate API URL if previewing browser and emulator simultaneously.

## Implemented behavior

- Resident tabs: Home, Map, SOS, Alerts, Profile. Camp Manager tabs: Overview, Center, Evacuees, Alerts, Profile. Expo Router guards each role using the exact backend values `residents` and `campmanager`; admin and other values are rejected.
- Android testing exposed a Fabric `MountingCoordinator::pullTransaction` crash with the default native-screen navigation path. The app retains Expo Router but uses a root `Slot`, disables native screens through the documented `enableScreens(false)` API, and keeps tab views attached. Tab transitions use a lightweight fade. This avoids the native stack teardown path; it is a tested workaround, not a claim that the upstream defect is fixed. [Upstream report with matching signature](https://github.com/software-mansion/react-native-screens/issues/4654). Reassess native stack navigation only after verifying an upstream fix on the target SDK.
- Login, resident self-registration, three-phase OTP recovery including resend, `/auth/me` restoration, supported profile fields, and logout use existing Laravel APIs. No role is submitted at registration. Avatar upload is outside this implementation's scope.
- The native token and 256-bit AES key are stored in SecureStore. Sensitive cached account and SOS records use authenticated AES encryption in the application document directory. No plaintext emergency details or credentials are written to AsyncStorage. Theme and the offline-saving preference use AsyncStorage.
- On restart, cached account access is retained while `/auth/me` is unavailable. Only HTTP 401 expires authentication. Account changes require successful session verification. Logout clears local credentials; if server revocation fails, the app states that the server token could not be revoked.
- SOS accepts the backend's nine required fields, GPS capture or manually supplied **known coordinates**, category, and priority. Coordinates remain mandatory because the backend requires them. The request whitelist always omits `status` and local metadata.
- Saving details is separate from sending. A manual confirmation dialog shows the complete payload. Pending drafts never send automatically on reconnect. The app prompts review of stored records when online.
- Before network I/O, the journal is persisted as **uncertain**. A crash, timeout, interrupted request, server error, or invalid receipt cannot silently become retryable. The backend has no idempotency key or public lookup; uncertain requests have no resend action. Laravel 422 validation and 429 rate-limit rejections return to pending. A received label requires HTTP 201 and a backend receipt ID/time. A receipt confirms storage, not dispatch or successful rescue.
- SecureStore values are bounded; only a small token/key is stored there, rather than a large SOS payload. Encrypted records have a 64 KiB limit. Storage, encryption, and replacement failures surface to the caller. An SOS is never sent if its pre-send journal cannot be saved. Same-record writes are serialized and authenticated before replacement. If the backend confirms a receipt but local saving fails, its ID is shown with a do-not-resend message.
- Camp Managers can read real SOS reports through the authorized list endpoint. Records are labeled caller reports, separately from official warnings, and show their fetch time. No center, occupancy, evacuee, or warning values are invented. Missing API actions are disabled.

## GIS and offline references

The native MapLibre map uses online OpenStreetMap raster tiles, application-identifying HTTP User-Agent, visible attribution, and no bulk downloading or prefetch feature. The initial center `[124.562, 10.109]` comes from the existing frontend's municipality map. It is not an evacuation destination. After foreground location approval, maps automatically show the current position and update it as the user moves. The shared GPS watcher stops in the background. Tap Locate me to request a fresh fix and recenter.

Six supplied `resources/Urban/* Urban Exposure Map.png` images are bundled without changing their legends or image content: flooding, groundshaking, liquefaction (original filename spelled “Liquifaction”), sea level rise, storm surge, and tsunami. They occupy about 16.8 MB. The `expo-asset` config plugin embeds them into Android drawable resources, and Android renders the local resource names directly; first viewing does not require downloading these images from Metro or the Internet. Android-compatible filenames use underscores. Images can be opened and zoomed/scrolled offline. The supplied Natural Resource set is a separate collection, not substituted for the chosen Urban set. No geographic overlay is applied because georeferencing and currency have not been verified.

Offline English guides are short paraphrases with source links and attribution to [PAGASA Floods](https://www.pagasa.dost.gov.ph/learning-tools/floods), [PHIVOLCS Earthquake Preparedness](https://www.phivolcs.dost.gov.ph/earthquake-preparedness/), and [PHIVOLCS Introduction to Tsunami](https://www.phivolcs.dost.gov.ph/introduction-to-tsunami/). They are not live warnings or evacuation orders.

**Full offline interactive basemaps are not implemented.** Cached online tiles are not a guarantee of coverage. [OSM's tile policy](https://operations.osmfoundation.org/policies/tiles/) prohibits bulk downloads/offline prefetch from its standard tile server. MapLibre's documented `OfflineManager.createPack` supports bounded offline regions, but only with a source whose license and serving policy allow those downloads, plus its style, fonts, and sprites. A future zero-cost option is to prepare appropriately attributed OSM-derived tiles for the municipality on the development computer, serve them locally, and download a bounded native pack. That requires an actual dataset, license/attribution review, storage sizing, and native pack testing; none is assumed to exist here.

## Notifications

`expo-notifications` is installed and typed preparation lives in `src/lib/notifications.ts`. No permission request, token registration, notification scheduling, fake event, or live push listener is activated. Missing requirements: an Android Firebase configuration matching `ph.islasafe.mobile`, backend FCM credentials, authenticated token lifecycle endpoints, an official alert source, and delivery/navigation policy. These should remain inactive until verified; no paid services are introduced.
